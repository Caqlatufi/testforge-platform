# TestForge 被测项目与 Jenkins 发布需求分析

> 核心业务闭环：测试工程师登记一个拥有 Git 仓库的被测项目；平台读取该项目绑定的 Jenkins Multibranch Pipeline；测试任务固定分支、Tag 或 Commit；执行时由 TestForge 控制发布时机、Jenkins 完成真实构建与发布，最终测试结果可追溯到项目、Commit 和 Jenkins Build。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 测试工程师、开发/DevOps、TestForge、Jenkins |
| 触发场景 | 项目首次接入，或某个分支、Tag、Commit 需要发布后执行自动化测试 |
| 当前问题 | 项目、测试任务、Jenkins 连接、测试环境和执行资源曾被混在同一表单中；本地 Jenkins SCM 镜像可能落后于任务冻结 Commit，且 checkout 前失败会因回调脚本尚未落盘而无法回传，造成 Deployment 永久停在 TRIGGERED |
| 期望结果 | Project 只表达被测项目；Jenkins 管理 Pipeline 和真实发布；TestForge 管理版本选择、发布请求、门禁与测试追溯 |
| 业务价值 | 测试人员不需要维护 Jenkins 内部配置，重复执行仍测试同一 Commit，并能从结果反查真实发布证据 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 开发/DevOps | 在项目仓库维护 Jenkinsfile，在 Jenkins 创建或扫描 Multibranch Pipeline | Jenkins 持有 SCM、分支目录、Agent 和发布逻辑 |
| 2 | 平台管理员 | 配置全局 Jenkins Connection，并把 Project 绑定到外部 Pipeline | Project 获得只读 Pipeline 目录 |
| 3 | 测试工程师 | 登记 Project 名称、应用类型、Git 仓库和默认分支 | Project 进入 ACTIVE |
| 4 | TestForge | 读取绑定 Pipeline 的分支、Tag 与最新构建信息 | 测试任务页面获得可选版本目录 |
| 5 | 测试工程师 | 创建测试任务并选择分支、Tag 或 Commit | 平台解析并冻结完整 Commit，同时固定 Pipeline 与 WorkflowVersion |
| 6 | TestForge | 任务执行时校验绑定与 Commit，选择满足 Case 需求的环境资源并触发 Jenkins | Deployment 进入 PENDING/BUILDING |
| 7 | Jenkins | 读取项目 Jenkinsfile，按约定参数初始化、构建并发布到指定资源 | 回传实际 Commit、Build URL 和 Endpoint/制品 |
| 8 | TestForge | 校验回调与发布输出；READY 后释放测试节点 | 测试结果关联 Project、Commit、Deployment 和 Build |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响步骤 |
| --- | --- | --- | --- |
| PD-R1 | 一个 Project 对应一个拥有 Git 仓库的被测项目；系统 ID 使用 UUID，页面不要求填写编码 | 创建、更新 | 3～8 |
| PD-R2 | Jenkins Connection 属于平台配置，不是 Project 参数 | Pipeline 读取与触发 | 2、4、6 |
| PD-R3 | Jenkins 是 Job、Jenkinsfile、SCM、Agent、构建和发布动作的真相源；TestForge 不创建或改写 Job | 接入与发布 | 1、2、6、7 |
| PD-R4 | Project 只绑定自己的外部 Pipeline；测试任务不能手填或伪造 Pipeline ID | 任务保存、执行 | 4～6 |
| PD-R5 | 分支和 Tag 选择后必须显示并冻结完整 Commit；指定 Commit 时仍保留来源分支上下文 | 版本选择 | 5～8 |
| PD-R6 | 重复执行同一测试任务不得漂移版本；需要新 Commit 时复制为新任务 | 重跑 | 5～8 |
| PD-R7 | Project 不拥有测试环境；环境、Agent、桌面和设备由执行资源域统一管理 | 资源分配 | 6～8 |
| PD-R8 | Jenkins 回传的实际 Commit 必须等于冻结 Commit；发布未 READY 时测试节点不得执行 | 回调、门禁 | 7、8 |
| PD-R9 | 可部署 Pipeline 必须支持 `INITIALIZE_ENVIRONMENT`；仅资源首次使用或被标记重置时为 true，成功后清除，失败后保留 | 空白环境发布 | 6～8 |
| PD-R14 | `INITIALIZE_ENVIRONMENT=true` 必须补齐应用真实启动所需的目录、数据库/权限等前置条件；管理员凭据由 Jenkins 受控环境提供，禁止写入仓库或回调载荷 | 空白环境初始化 | 6～8 |
| PD-R10 | 发布回调按 callbackKey、状态版本和载荷摘要幂等；迟到或冲突回调不得重复释放任务 | 回调 | 8 |
| PD-R11 | 本地演示的 Git daemon 裸镜像必须在仓库 Commit/合并后自动同步并验证冻结 Commit 可达；生产环境由项目正式远端仓库保证可达性 | 本地 SCM 更新、发布前 | 1、6、7 |
| PD-R12 | FAILED 回调不得依赖成功 checkout 后才存在的项目文件；PENDING/TRIGGERED/BUILDING 超过活动超时仍无终态时由 TestForge 收敛为 FAILED | 任意发布失败、回调丢失 | 6～8 |
| PD-R13 | 共享环境可通过 `pipelineJobNames` 声明兼容的 Jenkins Job；存在显式匹配时只在匹配环境中分配，未声明该配置的旧环境继续使用资源池兼容策略 | 自动选择发布环境 | 6、7 |

## 4. 异常分支

| 编号 | 异常场景/触发条件 | 系统处理 | 用户可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| PD-E1 | Git 仓库或默认分支无效 | 拒绝保存或版本解析 | 定位到仓库/分支字段 | Project 不可执行 |
| PD-E2 | Jenkins 不可用或凭据失效 | 保留 Project，只返回 Provider 错误 | Pipeline 目录显示不可用 | 不生成虚假 Pipeline |
| PD-E3 | Pipeline、分支或 Tag 已删除 | 执行前重验失败 | 要求刷新或重新选择 | 不创建 Deployment |
| PD-E4 | Commit 不存在或不属于选择上下文 | 版本解析失败 | 显示引用错误 | 不创建 Deployment |
| PD-E5 | Jenkins 入队、构建、初始化或发布失败 | 保存外部状态与 Build URL | 时间线显示发布失败阶段 | 测试节点 BLOCKED |
| PD-E6 | 实际 Commit 不一致或发布输出缺失 | 拒绝 READY | 显示版本/输出契约冲突 | Deployment FAILED |
| PD-E7 | 重复、乱序或迟到回调 | 幂等回读或拒绝冲突 | 返回 DUPLICATE/CONFLICT/STALE | 原状态不变 |
| PD-E8 | Jenkins Build 已失败或失联，但 FAILED 回调未到达 | 工作区无关回调优先上报；仍未上报则活动超时扫描收敛 | 时间线显示发布失败/回调超时，不再无限排队 | Deployment FAILED、测试节点 BLOCKED |
| PD-E9 | 目标系统存在环境，但都显式绑定给其他 Pipeline | 拒绝创建 Deployment，不回退到不兼容环境 | 显示“没有兼容 Pipeline 的测试环境实例” | 测试节点不进入发布队列 |

## 5. 本期包含

> 本期只实现下表明确列出的内容。未列出的能力一律不属于本期。

| 编号 | 能力或场景 | 完成边界 |
| --- | --- | --- |
| PD-IN1 | Project 管理 | 名称、UUID、应用类型、Git 仓库、默认分支和状态 |
| PD-IN2 | Pipeline 目录 | 从全局 Jenkins Connection 读取项目绑定的 Multibranch Pipeline、分支与 Tag |
| PD-IN3 | 版本冻结 | 分支、Tag、Commit 都解析为完整 Commit，并保存来源引用和描述 |
| PD-IN4 | Jenkins 发布控制 | 触发、状态同步、READY 门禁、回调幂等与发布证据 |
| PD-IN5 | 空白环境初始化契约 | 传递一次性初始化参数，由项目 Jenkinsfile 执行初始化阶段 |
| PD-IN6 | 页面收敛 | Project 页面只展示项目资产和只读 Pipeline 目录，不展示 Jenkins 连接、环境或并发配置 |
| PD-IN7 | 发布失败闭环 | 本地 SCM 自动同步、工作区无关 FAILED 回调、活动 Deployment 超时收敛和可辨识的等待发布状态 |
| PD-IN8 | 平台自测发布 | `testforge-platform/Jenkinsfile` 在普通分支构建时执行 CI，在 TestForge 触发时按冻结 Commit 发布独立测试实例并回调状态 |
| PD-IN9 | Pipeline 与共享环境兼容路由 | 环境配置声明兼容 Job；自动分配优先精确匹配，并向 Jenkins 传递实际发布键 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 | 对应规则 |
| --- | --- | --- | --- |
| PD-S1 | Project 表单只要求业务字段，ID 自动生成，响应不含环境所有权 | UI、OpenAPI、API 测试 | PD-R1、PD-R7 |
| PD-S2 | Jenkins 新增分支后由 Multibranch 扫描生成子 Job，TestForge 可读取但不修改 Job 配置 | Jenkins API 与 config.xml 对比 | PD-R2、PD-R3 |
| PD-S3 | 分支、Tag、Commit 选择后均显示 Commit 编号和描述，并在任务中冻结 | UI、任务快照核对 | PD-R5 |
| PD-S4 | 同一测试任务重复执行始终使用同一 Commit；复制任务后才能选择新版本 | 重跑与复制验收 | PD-R6 |
| PD-S5 | Jenkins READY 前测试节点不执行；READY 后结果可追溯到 Build URL 和实际 Commit | 真实 Jenkins Build | PD-R8 |
| PD-S6 | 初始化成功后不重复初始化，失败重试仍初始化；重复和迟到回调不重复释放任务 | 连续 Build 与故障注入 | PD-R9、PD-R10 |
| PD-S7 | 冻结 Commit 在 Jenkins 可获取时真实发布；缺失 Commit 或 checkout 失败能回传 FAILED；完全丢失回调时在活动超时后自动失败，页面不再长期显示普通 QUEUED | 镜像同步、真实 Jenkins Build、失败注入和超时测试 | PD-R11、PD-R12、PD-E8 |
| PD-S8 | 同平台存在多个资源池时，TestForge 只选择与当前 Pipeline 显式兼容的环境；单实例池向 Jenkins 传递该实例的 `providerEnvironmentKey` | 多环境真实发布与 Build 参数核对 | PD-R13、PD-E9 |
