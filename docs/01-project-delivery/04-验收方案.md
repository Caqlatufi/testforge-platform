# TestForge 被测项目与 Jenkins 发布验收方案

> 验收只认真实 Git/Jenkins 读取、真实 Build 与回调证据；Mock 或本地编译不能替代发布闭环。

## 1. 验收流程

### 1.1 验收准备

| 项目 | 要求 |
| --- | --- |
| 验收版本 | 固定 TestForge Commit、被测项目 Commit 和 Jenkinsfile Commit |
| 验收环境 | TestForge、Git 仓库、Jenkins Multibranch、至少一个可发布资源 |
| 测试数据 | 一个 Project、两个分支、一个 Tag、一个历史 Commit、一个初始化资源 |
| 证据目录 | `acceptance/evidence/project-delivery/` |

### 1.2 执行顺序

```mermaid
flowchart LR
    A[登记 Project 与 Pipeline] --> B[扫描分支/Tag]
    B --> C[冻结三个版本选择]
    C --> D[触发 Jenkins 发布]
    D --> E[验证 READY 门禁]
    E --> F[重跑同一测试任务]
    F --> G[注入初始化/回调异常]
    G --> H[归档 Build 与结果]
```

## 3. 并发验收

| 项目 | 验收口径 |
| --- | --- |
| 并发不变量 | 同一 deploymentKey 最多一个活动 Jenkins Build；同一回调只应用一次；READY 只释放一次节点 |
| 负载模型 | 20 路同时请求相同 Project、Commit、Pipeline 和 Allocation；20 路回调重放 |
| 并发量与持续时间 | 两组各 20 并发，请求完成后等待 Deployment 终态 |
| 执行步骤 | 并发创建发布请求；统计 Queue/Build；并发重放相同和冲突回调 |
| 达标指标 | 活动 Build=1、APPLIED=1、重复节点释放=0、错误 Commit READY=0 |
| 已知相邻影响检查 | ResourceClaim 不重复占用，Run/Task 最终状态唯一 |
| 证据要求 | Jenkins Queue/Build、HTTP 原始响应、Deployment/Task 数据与事件 |
