# TestForge 测试任务管理验收方案

## 1. 验收目标

验证用户能从测试任务草稿开始，选择 Project，使用通用/项目 Case 编排并发布一个 WorkflowVersion，固定 Commit 后确认并执行测试任务；同时确认重新执行只更新任务的当前结果、历史内部 Attempt 可审计，新流程没有 Suite 入口且历史 Suite 数据仍可读取执行。

## 3. 并发验收

| 项 | 验收口径 |
| --- | --- |
| 并发不变量 | 同一 Workflow 草稿 revision 不能被静默覆盖；发布版本不可变 |
| 执行步骤 | 两个客户端读取同一 revision 并分别保存；随后两个 Job 同时读取同一发布版本 |
| 达标标准 | 一个保存成功、一个明确冲突；两个 Job 的读取与启动互不修改 WorkflowVersion |
| 证据 | API 状态码、revision、发布 checksum、两个 TestJobSnapshot |

## 4. 自动化验证

| 层级 | 验证内容 |
| --- | --- |
| Java | Case scope、节点库隔离、跨 Project 引用拒绝、旧 Suite 编译兼容、Job 单版本绑定 |
| Vue | 默认导航、Project 级联、真实资产加节点、Suite 不出现、发布后回填 |
| Vue | 精简表单隐藏系统字段；优先级仅普通/紧急；保存载荷不含并发字段 |
| Vue | Workflow 二级视图互斥、工作台状态事件、返回与发布回填、节点库独立滚动结构 |
| Java/Vue | Git 分支/Tag 元数据、默认选择、页签切换、保存载荷与旧选择兼容 |
| 构建 | `gradlew test`、`npm test`、`npm run build` |
