# TestForge 测试任务管理需求分析

> 核心业务闭环：测试工程师创建一个归属被测项目的具体测试任务，在草稿内选定 Workflow 与 Git 引用并固化 Commit，确认后执行；重新执行只更新该任务的当前结果并保留内部 Attempt 历史，需要更换 Commit 时复制为新任务。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 测试工程师、Test Job 服务、Workflow 编排器、实时运行中心 |
| 触发场景 | 为一个被测项目建立可重复执行的回归、功能分支或双版本对比任务 |
| 当前问题 | Workflow 独立于任务暴露、要求手填 Project/Workflow ID；节点用随机引用占位；Suite 与 Workflow 重复表达一组 Case；导航主流程倒置 |
| 期望结果 | Workflow 是可复用拓扑定义，测试任务固定 Workflow 拓扑版本、Commit 和系统；Case 内容在每次内部执行创建时固化，运行中心不再暴露额外 Run 层级 |
| 业务价值 | 页面流程与测试人员真实工作顺序一致，避免无效引用和重复抽象，并保证运行可复现 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 测试工程师 | 进入测试任务页并新建草稿 | 创建本地编辑上下文，要求先选择 Project |
| 2 | 测试工程师 | 选择被测 Project | 加载该项目的已发布 Workflow、项目 Case、平台通用 Case、Fixture 与可复用 Subflow |
| 3 | 测试工程师 | 选择已有 WorkflowVersion，或进入二级工作台新建/编辑 Workflow | 主页面切换为视口内独立编排工作台；新 Workflow 始终归属当前 Project；节点只能选择真实资产 |
| 4 | 测试工程师 | 保存并发布 Workflow | 生成不可变 WorkflowVersion，并自动回填到当前 Test Job |
| 5 | 测试工程师 | 在分支/Tag 选择器中确认引用、Commit 与描述，再选择目标系统和优先级 | 保存时固化 Commit；任务确认后测试对象不可修改 |
| 6 | 操作人员 | 执行或重新执行任务并进入实时运行中心 | 页面展示该任务当前 Attempt 的工作流图；历史 Attempt 收入重试记录 |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响步骤 |
| --- | --- | --- | --- |
| TJ-R1 | Test Job 是用户主入口，必须归属一个 Project | 新建任务 | 1、2 |
| TJ-R2 | Workflow 必须归属 Project；未选择 Project 时不得创建、加载或编辑 Workflow | 编排 | 2、3 |
| TJ-R3 | 节点库由平台通用 Case、当前项目 Case、Fixture 与当前项目已发布 Subflow 组成；每个节点必须选择真实引用 | 编排 | 2、3 |
| TJ-R4 | 新编排只使用 CASE、FIXTURE、SUBFLOW；Suite 不再作为新资产或新节点，多个 Case 直接由 Workflow DAG 表达 | 编排 | 3 |
| TJ-R5 | 用户选择 Workflow，保存时自动取最新已发布拓扑版本并固化；一个 WorkflowVersion 可被多个测试任务引用 | 保存/确认 | 4、5 |
| TJ-R6 | SUBFLOW 是唯一的流程组合方式，且只能引用同 Project 已发布 WorkflowVersion，后端拒绝递归和环 | 编排/发布 | 3、4 |
| TJ-R7 | 旧 Suite 与含 Suite 的历史发布快照保持可读、可运行；新 UI 不再提供创建与新增入口 | 历史兼容 | 3、6 |
| TJ-R8 | 测试任务只有绑定发布拓扑版本与固定 Commit 后才能确认；每次 Attempt 创建时读取 Case 当前定义并固化自己的执行快照 | 确认/执行 | 5、6 |
| TJ-R9 | 主导航顺序为测试任务、实时运行、被测项目、环境资源；Workflow 编排属于 Test Job 草稿，不再作为顶层入口 | 页面导航 | 全流程 |
| TJ-R10 | Test Job 只声明 WINDOWS、ANDROID 或 IOS；资源池与具体测试机由平台内部路由和租赁 | 保存/启动 | 5、6 |
| TJ-R11 | Test Job 编码由后端生成 UUID，仅作系统稳定标识，不在创建表单展示或编辑 | 新建任务 | 1、5 |
| TJ-R12 | Pipeline 从 Project 已启用绑定中自动选择；没有可用 Pipeline 时保存失败 | 保存 | 5 |
| TJ-R13 | 优先级只有普通和紧急；不允许用户填写数值优先级 | 保存/调度 | 5、6 |
| TJ-R14 | Test Job 不接受用户并发承诺；实际并发由 READY 节点、Provider 容量、可分配资源和当前负载共同决定 | 保存/调度 | 5、6 |
| TJ-R15 | Workflow 编排必须在测试任务的二级独立工作台完成；桌面端页面外层不得滚动，节点资产与属性分别在自己的区域滚动 | 编排 | 3、4 |
| TJ-R16 | Git 版本只通过分支/Tag 目录选择；页面显示解析的 Commit 与描述，并在保存时固化；执行时不得重新解析移动分支 | 创建/编辑任务 | 2、5、6 |
| TJ-R17 | 选择 Project 后默认选择最近更新且已有发布版本的 Workflow；新建 Workflow 入口与选择器同一行 | 创建任务 | 2、3 |
| TJ-R18 | 创建表单按任务定义、测试内容、执行配置分区；Workflow 与 Git 版本属于主要测试内容，保存操作归入执行配置 | 创建/编辑任务 | 1、2、5 |
| TJ-R19 | 测试任务是用户可见的顶层执行对象；内部执行记录只表示 Attempt，不作为独立 Run 列表暴露 | 执行/重新执行 | 6 |
| TJ-R20 | 已确认任务的 Project、Workflow 拓扑版本、Commit 和目标系统不可修改；变化时复制为名称带数字后缀的新草稿；Case 内容更新不要求复制任务 | 编辑/复制、Case 保存 | 5、6 |
| TJ-R21 | 同一测试任务同一时刻最多一个非终态 Attempt；重新执行必须等待当前 Attempt 终态 | 重复执行 | 6 |

## 4. 异常分支

| 编号 | 异常场景 | 系统处理 | 用户可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| TJ-E1 | 未选择 Project 就进入编排 | 禁用编辑器和资产查询 | 提示先选择被测项目 | 草稿不变 |
| TJ-E2 | Case/Fixture/Subflow 不属于当前 Project 且不是平台通用 Case | 拒绝保存或发布 | 标出非法节点 | Workflow 草稿保留 |
| TJ-E3 | Workflow 尚未发布 | 不允许启用 Test Job | 提示先发布工作流 | Test Job 保持 DRAFT |
| TJ-E4 | Workflow 没有已发布版本 | 拒绝保存 Test Job | 提示先发布工作流 | 草稿不变 |
| TJ-E5 | 历史 Workflow 含 Suite | 使用遗留解析器加载和执行 | 标记“遗留 Suite，只读兼容” | 历史记录可用 |
| TJ-E6 | 通用 Case 被停用或删除 | 新发布拒绝引用；既有发布快照保持不可变 | 提示刷新节点库 | 不破坏历史执行证据 |
| TJ-E7 | Project 没有已启用 Pipeline | 拒绝保存 Test Job | 提示项目未配置可用 Pipeline | 草稿不变 |
| TJ-E8 | 当前系统没有满足能力的资源 | 当前执行保持排队，不突破租约和资源容量 | 实时运行中心显示等待资源及原因 | 配置不变，稍后继续调度 |

## 5. 本期包含

> 本期只做下表写明的能力，不实现表外内容。

| 编号 | 能力 | 完成边界 |
| --- | --- | --- |
| TJ-IN1 | 任务优先导航 | 测试任务作为默认首屏；移除顶层 Workflow 编排入口 |
| TJ-IN2 | 任务内工作流编排 | Test Job 草稿内选择已有发布版本，或创建、保存、发布当前 Project 的 Workflow |
| TJ-IN3 | 项目化节点库 | 自动加载平台通用 Case、项目 Case、Fixture 和项目 Subflow；点击真实资产生成节点 |
| TJ-IN4 | Suite 收敛 | 新 UI 移除 Suite 创建与节点入口；后端保留历史读取/执行兼容 |
| TJ-IN5 | 关系约束 | 一个 Test Job 固定一个 WorkflowVersion；发布版本可被多个 Test Job 复用 |
| TJ-IN6 | 平台型资源需求 | 保存目标系统，不向测试人员暴露环境或资源池选择 |
| TJ-IN7 | 系统参数自动化 | UUID 编码、最新 WorkflowVersion 和默认 Pipeline 由后端解析并固化 |
| TJ-IN8 | 简化优先级 | 页面只提供普通、紧急两个选项，默认普通 |
| TJ-IN9 | 负载驱动并发 | 页面和保存请求移除进程/设备并发；实际执行由资源租约与在线容量限流 |
| TJ-IN10 | 二级编排工作台 | 任务页只保留 Workflow 入口；进入后隐藏任务表单，以单视口工作台完成创建、编排、保存、发布与返回 |
| TJ-IN11 | 可读版本选择 | 分支/Tag 页签、真实引用目录、Commit SHA 与提交描述；默认分支自动选择 |
| TJ-IN12 | Workflow 默认值与入口布局 | 自动选择项目最新已发布 Workflow；新建按钮紧邻下拉菜单 |
| TJ-IN13 | 任务表单信息层级 | 宽屏下任务定义与测试内容并排、执行配置独立成底栏；窄屏自动纵向排列 |
| TJ-IN14 | 单层测试任务执行 | Commit 保存时固化；运行中心移除 Runs 主栏；重新执行形成内部 Attempt；支持同配置复制任务 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 |
| --- | --- | --- |
| TJ-S1 | 打开控制台默认进入测试任务，顶层没有独立 Workflow 页 | 浏览器检查导航与默认视图 |
| TJ-S2 | 选择 Project 前编排不可用；选择后只加载对应项目资产与平台通用 Case | 切换两个 Project 验证节点库 |
| TJ-S3 | 点击节点库真实 Case 可生成有效节点，保存发布无需手填 UUID | 浏览器创建并发布 Workflow |
| TJ-S4 | 页面不能新建 Suite 或 Suite 节点；旧含 Suite 发布版本仍可查询和运行 | 新旧数据各验证一次 |
| TJ-S5 | Test Job 保存后只含一个 workflowId/version，同一版本可供两个 Job 引用 | API 与数据库检查 |
| TJ-S6 | Test Job 请求只含 platform，不含 environmentExternalId/resourcePoolKey | 页面与请求载荷检查 |
| TJ-S7 | 创建表单不显示编码、固定版本、Pipeline 和两个并发输入，新建任务仍能成功 | DOM 与真实 API 检查 |
| TJ-S8 | 后端生成 UUID 编码，并固化所选 Workflow 的最新发布版本与项目默认 Pipeline | TestJobView 与数据库检查 |
| TJ-S9 | 优先级只能选择普通或紧急；交互任务数量大于空闲目标数时只按有效资源 Lease 执行 | 页面检查与双 VM 运行观察 |
| TJ-S10 | 进入 Workflow 后任务列表和表单不再同屏，页面主体无纵向滚动；左侧节点资产超高时独立滚动 | 组件断言与浏览器视口检查 |
| TJ-S11 | 项目切换后 Workflow 和默认分支自动选中；版本摘要显示引用、短 SHA 与提交描述，分支/Tag 可切换 | API、DOM 与保存载荷检查 |
| TJ-S12 | 创建表单三区边界清晰；宽屏与 900px 视口下字段、按钮和版本摘要无重叠 | 浏览器双视口检查 |
| TJ-S13 | 同一任务连续两次执行使用相同 Commit；运行中心只显示任务与当前详情，重试历史可追溯但无独立 Runs 主栏 | API、数据库快照与浏览器检查 |
| TJ-S14 | 复制任务自动生成未占用的 `-N` 名称并保留原 Commit；已确认任务修改测试对象返回冲突 | API 与数据库检查 |
