# TestForge 平台工程、控制台与交付验收方案

> 本文既验证 PD-S1～PD-S5，也定义全平台固定主流程回归。各功能已知相邻影响在本功能验收中检查；难以穷举的跨功能影响由本固定回归在主干合并、夜间构建和发布候选阶段统一发现。

## 1. 验收流程

### 1.1 验收准备

| 项目 | 要求 |
|---|---|
| 验收版本 | 固定根仓、子项目 commit、契约版本和制品摘要 |
| 干净环境 | Java 21、Node、Python、Docker 可用且无本地缓存状态依赖 |
| 运行依赖 | Compose 服务均通过健康检查，真实 Provider 登录状态单独记录 |
| 测试数据 | 准备 acceptance/fixtures/http、Skill Sandbox UI、失败诊断及可靠性数据集 |
| 证据目录 | 按 commit 保存构建、契约、API、可靠性、Provider、UI 和文档证据 |

### 1.2 交付与固定回归顺序

```mermaid
flowchart LR
    A[干净环境检出] --> B[契约与模块门禁]
    B --> C[根构建与 Compose 健康检查]
    C --> D[创建被测 Project并读取 Pipeline]
    D --> E[创建 YAML Case 与脚本资源]
    E --> F[编排并发布 Workflow]
    F --> G[创建 Test Job 并执行]
    G --> H[Provider/Agent 回调证据并生成报告]
    H --> I[AI 成功与降级检查]
    I --> J[MCP Host 获取上下文并执行任务]
    J --> K[核对文档与提交可追溯性]
```

固定主流程回归在以下时机执行：

- 功能分支合并主干后；
- 夜间构建；
- 发布候选版本生成后。

## 2. 流程验收场景

| 场景编号 | 覆盖的成功标准 | 前置条件 | 操作 | 预期结果 | 已知相邻影响检查 | 证据要求 |
|---|---|---|---|---|---|---|
| PD-AC-01 | PD-S1 | 全新检出且工具链版本满足 README | 执行根 build/check 入口 | 后端、前端、Worker、契约与测试均通过，失败可定位到子步骤 | 产物版本和契约摘要一致 | 环境清单、命令、完整输出、制品摘要 |
| PD-AC-02 | PD-S2 | Compose 配置已加载 | 启动全部依赖并执行 HTTP 与 UI 端到端样例 | 所有依赖健康，主链路无需改库即可运行 | 观测、对象存储和消息链路均可追溯 | 健康检查、端到端日志、截图和报告 |
| PD-AC-03 | PD-S3 | 可在临时分支注入错误 | 分别制造不兼容契约和非法模块依赖并运行门禁 | 构建被阻断且输出明确指出契约或依赖原因 | 恢复改动后同一门禁重新通过 | 失败与恢复输出、规则定位 |
| PD-AC-04 | PD-S4 | 验收环境和 evidence 根目录已准备 | 依次执行真实 API、可靠性、Provider 和 UI 验收 | 每类输出均含命令、断言、环境、状态和证据路径 | 汇总结果不把构建或 Mock 冒充真实验收 | 验收索引、各类原始报告和路径校验 |
| PD-AC-05 | PD-S5 | 任取一个已完成 worker 任务 | 核对代码、任务档案、对应项目文档及 Foreman 合并提交 | 四类材料位于同一可追溯提交范围，项目文档未在合并时遗漏 | 合并后文档链接和目录索引有效 | worker commit、Foreman commit、档案与文档 diff |
| PD-AC-06 | PD-S8 | TestForge API 和至少一个 Project/Test Job 可用 | 在 MCP Inspector 和至少一个真实 MCP Host 中发现能力；检查 Workspace、执行既有 Test Job、读取执行与报告；另验证错误地址和越界路径 | Host 能发现约定 Tools、Resources、Prompts；写操作回显 requestKey；失败返回结构化错误且 stdout 无协议外日志 | Web Console 可读取同一任务和报告 | Inspector/Host 输出、MCP stderr、TestJob/Execution/Report ID |

### 2.1 固定主流程回归

| 场景编号 | 触发时机 | 固定流程 | 通过标准 | 证据要求 |
|---|---|---|---|---|
| PD-RG-01 | 主干合并 / 夜间 / 发布候选 | Project → Case/Script → Workflow 发布 → Test Job 固定 Commit → Jenkins 发布 → Provider/Agent 执行 → 报告 | 全链路从零完成，页面、API、事件和持久化终态一致 | 全程 API 输出、TestJob/Attempt/Report ID、日志、页面录屏 |
| PD-RG-02 | 主干合并 / 夜间 / 发布候选 | 派发重放、Agent 宕机恢复、交互资源租赁、SSE 重连 | 不丢任务、不产生重复有效结果、资源不双占、最终页面与 REST 一致 | 可靠性脚本、状态时间线、监控和数据核对 |
| PD-RG-04 | 主干合并 / 发布候选 | 四个主导航、宽屏/窄屏布局、加载/空/错/降级状态 | 统一视觉可读，业务页面无主视口双滚动，状态不只用颜色表达 | 组件测试、双视口截图、可访问性检查 |
| PD-RG-03 | 夜间 / 发布候选 | 真实 Provider 诊断及 Provider 不可用降级 | 成功诊断证据可回溯；降级不影响权威报告 | Provider 元数据、诊断结果、报告前后 diff、页面截图 |
| PD-RG-05 | 主干合并 / 发布候选 | MCP 能力发现 → 工作区与项目上下文 → 执行既有 Test Job → 读取 Execution/Report | MCP 与 Web/API 数据一致；同 requestKey 重试不产生第二次有效执行 | MCP Host 输出、API 查询、页面截图、requestKey |

### 验收结论

| 项目 | 结论 |
|---|---|
| 交付流程 | PASS（本地） |
| 固定主流程回归 | NOT_RUN |
| 阻塞问题 | 新资源模型的 ResourceClaim/Container Provider/Agent API 尚未完成，固定主流程需在完成后重跑 |
| 最终结论 | 平台构建与本地 Compose smoke 已有通过证据；当前完整端到端交付验收未完成 |
