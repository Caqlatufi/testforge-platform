# TestForge 平台工程、控制台与交付需求分析

> 核心业务闭环：开发者在干净环境中依据同一套契约构建并启动 Java 控制面、Vue Console、Python Worker 和基础设施，测试人员执行真实验收并产出可追溯交付证据。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 搭建和修改平台的开发者、执行验收的测试工程师、按固定路径展示系统的演示者，以及通过 MCP Host 调用平台的 AI Agent |
| 触发场景 | 新机器首次搭建、功能变更准备合并、发布候选版本需要验证或演示 |
| 当前问题 | 多语言项目若缺少模块边界、统一契约、可复现基础设施和验收门禁，会出现本机可运行但无法重建、跨端字段漂移和证据不可追溯；AI 直接拼装 REST 请求又缺少标准能力发现、工作区边界和结构化调用入口 |
| 期望结果 | 一套明确入口完成契约校验、各子项目构建、依赖启动、统一控制台呈现、MCP Host 调用、真实 HTTP/可靠性验收和证据归档 |
| 业务价值 | 把分散实现收敛为可重建、可验证、可讲解的 TestForge v0.1 交付物 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 开发者 | 在文档中确认需求、架构、开发和验收范围 | 形成可执行的开发边界和验收口径 |
| 2 | 开发者 | 更新 OpenAPI、JSON Schema 和合法/非法示例 | Java、TypeScript、Python 共享同一版本化契约 |
| 3 | 开发者 | 执行根构建/验证入口 | 校验模块依赖、后端、前端、Worker 和契约 |
| 4 | 开发者 | 使用 Compose 启动 MySQL、Redis、MinIO 和观测组件 | 各依赖通过健康检查并提供可复现环境 |
| 5 | 开发者/测试工程师 | 启动应用、Worker、Console 和样例服务 | 端到端主链路具备真实运行条件 |
| 6 | 测试工程师 | 执行 Bruno、HTTP、可靠性和浏览器验收 | 分类型记录真实请求、断言、日志和界面证据 |
| 7 | 任务 Worker/Foreman | 更新任务文档和项目文档并合并提交 | 代码、契约、证据和长期文档形成同一交付闭环 |
| 8 | AI Agent/MCP Host | 通过 `testforge-mcp` 发现受控工作区和平台能力、维护测试资产、执行任务并读取报告 | MCP 返回结构化 Tool 结果、Resources 和可追溯 requestKey |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响的流程步骤 |
| --- | --- | --- | --- |
| PD-R1 | `app` 是唯一 bootJar，其他 Java 模块只生成普通 jar | Gradle 构建 | 3 |
| PD-R2 | 后端模块依赖必须匹配约定矩阵，无循环依赖，不绕过公开边界访问其他模块的持久化数据 | 编译和边界校验 | 3 |
| PD-R3 | OpenAPI 和 JSON Schema 以 manifest 为入口，同一主版本只允许向后兼容新增 | 契约变更 | 2、3 |
| PD-R4 | 消息携带明确 schemaVersion；消费者拒绝缺失必填字段并忽略未知可选字段 | 跨语言通信 | 2、5、6 |
| PD-R5 | 真实密钥仅通过环境变量注入，不提交本地私密配置 | 配置环境 | 4、5 |
| PD-R6 | Compose 服务必须通过各自健康检查；容器已启动不等于依赖可用 | 环境启动 | 4、5 |
| PD-R7 | 新实体和普通字段默认由 JPA DDL update 承接；视图、索引和兼容数据才进入 simple-migration | 数据演进 | 3、5 |
| PD-R8 | 单测、构建、mock、真实 HTTP、真实 Provider 和手工 UI 证据必须分开标识 | 验收与结论 | 6 |
| PD-R9 | 每个任务在自己的 worktree 同时更新任务档案和受影响的项目文档，Foreman 语义合并 | 任务完成和合并 | 7 |
| PD-R10 | Web Console 只提供顶层导航、通用请求/状态处理和统一视觉系统；业务页面规则留在所属功能域 | 页面开发 | 5、6 |
| PD-R11 | 平台自身 CI 由 `testforge-platform/Jenkinsfile` 定义并由 Jenkins Multibranch 执行；被测项目发布使用各自仓库 Jenkinsfile | 分支构建、合并门禁 | 3、6 |
| PD-R12 | `testforge-mcp` 是独立 Go MCP Server，只调用公开 REST API，不直连 MySQL、Redis、Jenkins 或 Worker；stdio stdout 只承载 MCP，诊断写 stderr | AI/MCP 调用 | 8 |
| PD-R13 | MCP 写 Tool 与只读 Tool/Resource 名称明确分离；执行和发布接受或生成 requestKey，使 Agent 重试不绕过平台幂等边界 | AI/MCP 写入 | 8 |
| PD-R14 | TestForge Platform 可以作为普通被测 Project 登记；其 UI 自测必须经 Jenkins 发布独立实例，并由 `playwright-web` Worker 只通过浏览器页面操作 | 平台自测 | 3、5、6 |
| PD-R15 | 一级导航状态必须写入 URL；异步数据未返回前显示加载态，不得短暂伪装为空数据 | Console 使用 | 5、6 |

## 4. 异常分支

| 编号 | 异常场景/触发条件 | 系统处理 | 用户或调用方可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| PD-E1 | 模块依赖不符合矩阵或出现循环 | 构建门禁失败并指出违规模块 | 开发者获得明确依赖差异 | 不生成合格交付物 |
| PD-E2 | 契约删除必填字段或示例不符合 Schema | 契约校验失败 | 输出不兼容位置和文件 | 实现不得继续冒充兼容版本 |
| PD-E3 | Compose 服务启动但健康检查未通过 | 阻止进入真实验收 | 显示失败依赖及健康状态 | 环境标记未就绪 |
| PD-E4 | 缺少 MCP Host、账号、测试数据或运行服务 | 对相关验收标记 NOT_RUN 并记录缺失条件 | 不把构建或 mock 通过写成真实验收通过 | 交付结论保留未验证项 |
| PD-E5 | Worker 提交代码但未更新项目文档 | 不满足任务完成门槛 | Foreman 拒绝标记 done 或要求补齐 | 文档与代码不分离合并 |
| PD-E6 | 多个 Worker 修改同一项目文档 | Foreman 按章节和事实语义合并 | 保留各任务结论和证据 | 不使用整体 ours/theirs 覆盖 |
| PD-E7 | MCP 无法连接、API 返回失败或响应缺少 data | 返回结构化 OperationResult、平台错误和 traceId | Agent 可根据错误类型停止、修正或重试 | 不把失败输出伪装成业务数据 |
| PD-E8 | MCP Tool 参数、工作区路径或本地文件无效 | 在发出业务写请求前拒绝 | 返回稳定错误码；越界路径不泄露内容 | 平台数据不变 |

| PD-IN1 | Java 工程骨架 | Gradle 模块清单、依赖边界、唯一 bootJar 和统一验证 |
| PD-IN2 | 跨语言契约 | OpenAPI、任务消息、回调、事件、附件 Schema 与示例 |
| PD-IN3 | 本地基础设施 | MySQL、Redis、MinIO、Prometheus、Grafana 的 Compose 配置和健康检查 |
| PD-IN4 | 构建与启动入口 | Windows/Linux 可用的现有脚本、环境示例和执行说明 |
| PD-IN5 | 验收体系 | Bruno、真实 HTTP、可靠性场景、浏览器检查和分类证据 |
| PD-IN6 | 交付资料 | README、项目文档、任务档案、演示步骤和可追溯证据 |
| PD-IN7 | Web Console 外壳 | 主导航、请求层、加载/空/错/降级状态、设计令牌和响应式布局 |
| PD-IN8 | Jenkins 分支 CI | Java、Python、Node、契约和 Compose 冒烟作为平台 Jenkinsfile 阶段并归档结果 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 | 对应流程/规则 |
| --- | --- | --- | --- |
| PD-S1 | 干净环境执行根构建/验证后，后端、前端、Worker 和契约全部通过 | 按 README 在新环境执行脚本 | 流程 2、3，PD-R1～R4 |
| PD-S2 | 所有 Compose 依赖通过健康检查，平台主链路可在不改数据库的情况下运行 | 启动环境并执行端到端样例 | 流程 4、5，PD-R5、R6 |
| PD-S3 | 不兼容契约和非法模块依赖都会阻断构建并定位原因 | 注入契约及依赖错误 | PD-E1、PD-E2 |
| PD-S4 | 真实 API、可靠性、Provider 和 UI 验收分别记录命令、断言、环境、结果和证据路径 | 核对验收输出与 evidence 目录 | PD-R8、PD-E4 |
| PD-S5 | 任一完成任务的代码、任务档案和项目文档存在于同一可追溯提交范围 | 抽查 worker commit 和 Foreman 合并结果 | 流程 7，PD-R9、PD-E5、E6 |
| PD-S6 | 四个主导航页面使用一致框架、状态色和可读字号；业务交互仍由各功能域测试覆盖 | 浏览器双视口与组件测试 | PD-R10 |
| PD-S7 | Jenkins Multibranch 对平台分支执行完整 Jenkinsfile，任一阶段失败都会阻断并保留日志 | 真实 Jenkins Branch Build | PD-R11 |
| PD-S8 | MCP Host 可发现 `testforge-mcp` 能力，并通过结构化 Tool/Resource 获取项目上下文、创建并执行测试任务、读取报告 | MCP 内存会话、真实 Host 与真实 API 验收 | PD-R12、PD-R13、PD-E7、PD-E8 |
| PD-S9 | TestForge 能发布自身独立测试实例并调度 Playwright 完成全 UI 操作，报告包含截图、Trace 和日志 | 真实 Jenkins Build、Web Console 操作和 TestForge Report | PD-R14、PD-R15 |
