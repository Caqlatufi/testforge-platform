# TestForge 执行编排与可靠性需求分析

> 核心业务闭环：操作人员执行一个已确认的测试任务；平台按该任务固定的 Commit 和 Workflow 拓扑版本读取 Case 当前定义，先创建不可变 execution snapshot，再把 DAG 节点转成可调度 Task；最终测试任务展示本次结果，重新执行覆盖当前展示但保留内部历史。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 执行测试任务的测试工程师、运行编排器、Dispatcher、Execution Provider |
| 触发场景 | 首次执行、重新执行、取消测试任务，或执行中发生重复消息、Agent 失联和迟到回调 |
| 当前问题 | 历史页面把 Test Job 和 Run 同时作为用户对象；至少一次投递又会带来重复领取、回调和终态竞争 |
| 期望结果 | 用户只操作测试任务；内部 Attempt 可追溯；DAG、派发、租约、重试和取消最终收敛到唯一结果 |
| 业务价值 | 执行模型贴近 CI 任务体验，同时保留面试可解释的分布式调度和故障恢复证据 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 操作人员 | 执行 ACTIVE Test Job | 校验当前无活动执行，读取固定 Commit/拓扑版本和 Case 当前定义 |
| 2 | 运行编排器 | 创建内部 JobExecutionAttempt，先固化 execution snapshot，再拆分 Task 和依赖 | 根节点 READY，其余等待依赖 |
| 3 | 运行编排器 | 为 READY Task 登记事务 Outbox，并由资源域生成 ResourceClaim | MySQL 同时保存状态、事件与派发意图 |
| 4 | Dispatcher | 消费待执行消息并为 Claim 分配 Provider/资源 | 分配成功后创建 TaskAttempt 与租约 |
| 5 | Provider/Agent | 上报开始、心跳、证据和终态 | Task 收敛；成功或完成条件释放后继 |
| 6 | 运行编排器 | 所有 Task 终态后聚合执行结果 | Test Job 当前结果更新，内部 Attempt 留在历史 |
| 7 | 操作人员 | 重新执行同一 Test Job | 使用相同 Project、Commit、WorkflowTopologyVersion 和目标系统，但重新固化当时 Case 当前定义 |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响步骤 |
| --- | --- | --- | --- |
| EO-R1 | Test Job 是唯一用户可见执行对象；内部 JobExecutionAttempt 不作为独立主列表 | 查询、展示 | 1～7 |
| EO-R2 | 同一 Test Job 同一时刻最多一个非终态 JobExecutionAttempt | 执行、重跑 | 1、7 |
| EO-R3 | 重跑必须复用任务固定的 Commit、WorkflowTopologyVersion、Pipeline 和目标系统；Case 内容取重跑创建时当前定义；更换任务固定项必须复制任务 | 执行、重跑 | 1、7 |
| EO-R4 | 根 Task 初态 READY；其他 Task 等待 DAG 依赖；ON_SUCCESS 与 ON_COMPLETION 按发布快照释放 | 拆解、终态 | 2、5 |
| EO-R5 | 前置失败只阻断显式后继子图，无关分支继续 | DAG 收敛 | 5 |
| EO-R6 | Task/TaskAttempt 使用 state+version 条件更新；同一 Task 同时最多一个有效 TaskAttempt | 领取、回调、恢复 | 4、5 |
| EO-R7 | Outbox、业务状态和执行事件同事务写入；Redis 只承载可重复派发 | 派发 | 3 |
| EO-R8 | 实际并行度由 READY 节点、Dispatcher 数量、Provider 和实时资源决定，不读取测试任务并发输入 | 调度 | 3～5 |
| EO-R9 | Agent/Provider 失联后旧 TaskAttempt 先 LOST，再按失败分类和重试策略恢复 | 故障恢复 | 5 |
| EO-R10 | 旧 leaseToken、旧 TaskAttempt 或冲突回调只留审计，不覆盖当前结果 | 回调 | 5 |
| EO-R11 | 取消后停止释放新节点；活动 TaskAttempt 在有限时间内取消或由 Reaper 收敛 | 取消 | 5、6 |
| EO-R12 | 取消仍在等待发布的执行时，若其 Deployment 未被其他活动执行引用，必须立即将 Deployment 收敛为 FAILED 并释放环境初始化/容量锁 | 取消、发布等待 | 5、6 |

## 4. 异常分支

| 编号 | 异常场景/触发条件 | 系统处理 | 用户可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| EO-E1 | 同一任务已有活动执行 | 拒绝第二次启动 | 提示等待当前执行结束 | 不创建新 Attempt |
| EO-E2 | 重复执行请求使用同一 requestKey | 返回已有内部 Attempt | 当前执行保持不变 | 无重复副作用 |
| EO-E3 | Redis 暂时不可用 | Outbox Relay 保留并退避重试 | 显示派发延迟 | MySQL 状态不丢失 |
| EO-E4 | Provider/Agent 在执行中失联 | 租约过期、旧 TaskAttempt LOST、Claim 重新规划 | 时间线显示资源切换 | 新 TaskAttempt 继续或失败 |
| EO-E5 | 旧执行迟到回调 | 返回 STALE 并追加审计事件 | 当前结果不变 | 新执行权威 |
| EO-E6 | 前置 Task 失败 | 按边条件释放或阻断后继 | DAG 标出 blockedBy | 无关分支继续 |
| EO-E7 | 用户取消 | 停止新派发并收敛活动执行 | 显示取消进度 | CANCELED |
| EO-E8 | 用户取消时 Jenkins 尚未回调终态 | 取消等待节点；仅在没有其他活动执行共享该 Deployment 时将其标记失败 | 环境可立即被下一个任务分配 | CANCELED / Deployment FAILED |

## 5. 本期包含

> 本期只实现下表明确列出的内容。未列出的能力一律不属于本期。

| 编号 | 能力或场景 | 完成边界 |
| --- | --- | --- |
| EO-IN1 | 单层测试任务执行 | 执行、重新执行、取消和当前结果展示；内部 Attempt 只作历史 |
| EO-IN2 | DAG 调度 | 节点拆解、ON_SUCCESS/ON_COMPLETION、BLOCKED 与聚合 |
| EO-IN3 | 可靠派发 | 事务 Outbox、Redis Streams、重复消息幂等和 Relay 恢复 |
| EO-IN4 | TaskAttempt 生命周期 | 领取、开始、心跳、完成、失败、LOST、取消和迟到隔离 |
| EO-IN5 | 动态资源协同 | READY 节点生成 Claim；执行资源域决定真实并行度 |
| EO-IN6 | 故障恢复 | Agent/Provider 失联、有限重试、并发回调和取消竞争 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 | 对应规则 |
| --- | --- | --- | --- |
| EO-S1 | 运行中心只显示 Test Job 和当前执行图，重试历史可展开但没有独立 Runs 主栏 | 浏览器与 API 检查 | EO-R1 |
| EO-S2 | 同一任务连续执行两次使用同一 Commit 与 WorkflowTopologyVersion，且不会并行启动两个执行；两次 Run 分别冻结各自创建时的 Case | API、快照与并发启动 | EO-R2、EO-R3 |
| EO-S3 | 混合成功/失败 DAG 的释放、阻断和最终聚合与发布快照一致 | DAG 集成验收 | EO-R4、EO-R5 |
| EO-S4 | 重复创建、消息、领取和回调不产生第二个有效执行结果 | 重放与数据库核对 | EO-R6、EO-R7、EO-R10 |
| EO-S5 | 连续三次终止执行 Agent 后均能形成 LOST 记录并由新 TaskAttempt 收敛 | 故障注入 | EO-R9 |
| EO-S6 | 取消与完成竞争时只产生一个合法终态，资源最终全部释放 | 并发取消验收 | EO-R11 |
| EO-S7 | 取消 WAITING_DEPLOYMENT 执行后，未共享的活动 Deployment 立即失败，下一任务不再收到环境 423 锁定 | UI 取消后立即启动新任务 | EO-R12 |
