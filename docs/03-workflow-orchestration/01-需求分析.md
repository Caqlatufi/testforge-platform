# TestForge 项目工作流编排需求分析

> 核心业务闭环：测试工程师在测试任务草稿中选择 Project，使用平台通用 Case、项目 Case/Fixture 和已发布 Subflow 编排无环流程；发布后得到不可变的 DAG 拓扑版本。每次创建执行时，平台再用该拓扑解析 Case 当前定义并固化独立执行快照。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 创建测试任务和编排执行流程的测试工程师、Workflow 编译器、运行编排器 |
| 触发场景 | 测试任务需要选择现有工作流，或在任务草稿中创建/修改项目工作流 |
| 当前问题 | 独立 Workflow 页面要求手填项目和引用 ID；节点可能没有真实资产；无边节点集合又难以解释实际并行流程 |
| 期望结果 | Workflow 强归属 Project，通过任务二级工作台编排真实资产；WorkflowVersion 固定结构，Run 快照固定实际执行内容 |
| 业务价值 | 测试人员按“创建任务—选择/编排流程—发布—执行”的顺序工作，DAG 可读、可复用、可追溯 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 测试工程师 | 在 Test Job 草稿选择 Project | 自动加载该项目最近发布 Workflow 和节点资产目录 |
| 2 | 测试工程师 | 选择已有 Workflow，或进入二级单视口工作台新建/编辑 | 工作台固定当前 Project，左侧资产栏独立滚动 |
| 3 | 测试工程师 | 将 CASE、FIXTURE、SUBFLOW 加入画布并连接依赖边 | 草稿保存真实 referenceId、坐标、属性和边条件 |
| 4 | 前端/后端 | 校验节点归属、参数、自依赖、重复边、环和 Subflow 递归 | 非法图保留草稿但不得发布 |
| 5 | 测试工程师 | 发布 Workflow | 保存不可变 displaySnapshot、Case 引用、Subflow 引用与拓扑 checksum |
| 6 | Test Job | 接收发布结果 | 自动绑定最新 Workflow 拓扑版本 |
| 7 | 运行编排器 | 创建执行 | 按拓扑读取 Case 当前 YAML/脚本，展开 Subflow，生成不可变 executionSnapshot 后再创建 Task |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响步骤 |
| --- | --- | --- | --- |
| WF-R1 | Workflow 必须归属 Project；未选择 Project 时不得创建、加载或编辑 | 进入编排 | 1、2 |
| WF-R2 | 新节点类型仅限 CASE、FIXTURE、SUBFLOW，且必须引用平台通用或当前项目真实资产 | 添加、保存、发布 | 2～5 |
| WF-R3 | Workflow 必须是有向无环图；拒绝自依赖、重复边、孤立非法引用和 Subflow 递归 | 校验、发布 | 3～5 |
| WF-R4 | 边条件仅为 ON_SUCCESS 或 ON_COMPLETION，并直接决定运行时后继释放 | 连线、编译 | 3～5 |
| WF-R5 | WorkflowVersion 的 displaySnapshot 保留用户节点、坐标、真实边与 Case/Subflow 引用；它是拓扑版本，不是 Case 内容版本 | 发布 | 5、6 |
| WF-R6 | WorkflowVersion 发布后不可变；修改节点或边必须产生新草稿和新版本；修改 Case 不产生 WorkflowVersion | 编辑、发布 | 2～6 |
| WF-R7 | 一个 WorkflowVersion 可供多个 Test Job 引用；每个 Test Job 固定一个拓扑版本 | 任务保存 | 1、6 |
| WF-R8 | 没有显式依赖的多个根节点语义为并行；运行中心可补充虚拟开始、汇总和完成边，但不得改变调度语义 | 编排、回放 | 3、6 |
| WF-R9 | Suite 不进入新节点库；旧 SUITE 节点只通过兼容编译器加载和执行 | 兼容读取 | 2、5 |
| WF-R10 | 编排工作台是任务页的二级独立页面；主视口不滚动，资产栏和属性栏各自滚动 | 页面 | 2～5 |
| WF-R11 | Case 保存后，所有引用该 Case 的 Workflow 后续执行自动使用新定义，无需重新发布 Workflow | Case 保存、执行创建 | 5～7 |
| WF-R12 | executionSnapshot 在执行记录创建事务内生成并保存；QUEUED、RUNNING 和终态执行均不得回读最新 Case | 执行创建、回放 | 7 |
| WF-R13 | 可执行 Case 必须恰好拥有一个主脚本入口；一个主脚本可以携带多个辅助文件，但不能有多个可选择主入口 | Case 校验、执行解析 | 7 |

## 4. 异常分支

| 编号 | 异常场景/触发条件 | 系统处理 | 用户可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| WF-E1 | 未选择 Project | 禁用编排入口与资产加载 | 提示先选择项目 | Test Job 草稿不变 |
| WF-E2 | 节点跨项目或引用已失效 | 拒绝保存/发布并定位节点 | 画布标红非法节点 | 草稿保留 |
| WF-E3 | 图存在环、自依赖或重复边 | 后端权威校验拒绝发布 | 显示具体边或环路径 | 不产生版本 |
| WF-E4 | Subflow 未发布或递归引用 | 停止编译 | 显示引用链 | 不产生部分快照 |
| WF-E5 | 创建执行时 Case YAML/Asset 无效、缺失或跨项目 | 拒绝创建执行并指出 Case | 要求修复 Case 后重试 | 不产生 Run/Task 半成品 |

## 5. 本期包含

> 本期只实现下表明确列出的内容。未列出的能力一律不属于本期。

| 编号 | 能力或场景 | 完成边界 |
| --- | --- | --- |
| WF-IN1 | 任务内二级工作台 | 选择 Project 后进入独立单视口编排页并返回任务 |
| WF-IN2 | 项目化节点库 | SHARED Case、项目 Case/Fixture、项目已发布 Subflow |
| WF-IN3 | DAG 编辑 | 添加、移动、连接、删除、撤销/重做、自动布局和属性编辑 |
| WF-IN4 | 权威校验 | 归属、引用、参数、自依赖、重复边、环和递归校验 |
| WF-IN5 | 拓扑发布与执行解析 | 发布时保存 topology snapshot；执行创建时展开 Subflow 并固化 Case YAML、脚本 URI、SHA-256 和执行需求 |
| WF-IN6 | 运行回放 | 真实依赖边加实线；并行无边图补虚拟开始/汇总/完成虚线 |
| WF-IN7 | Suite 兼容 | 新编排不展示 Suite；旧节点可读、可编译、可执行 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 | 对应规则 |
| --- | --- | --- | --- |
| WF-S1 | 未选 Project 时不能编排；切换 Project 后节点库只显示合法资产 | 两项目浏览器验收 | WF-R1、WF-R2 |
| WF-S2 | 真实 Case/Fixture/Subflow 可通过点击加入，无需手填 UUID | 创建并保存草稿 | WF-R2 |
| WF-S3 | 自依赖、重复边、环、跨项目和递归 Subflow 均被后端拒绝并定位 | API 故障用例 | WF-R3、WF-E2～E4 |
| WF-S4 | 修改 Case 后不产生新 WorkflowVersion；下一次执行快照使用新脚本，而修改前已创建执行的快照、Task 和结果保持不变 | 两次执行快照对比 | WF-R5、WF-R6、WF-R11、WF-R12 |
| WF-S5 | 同一拓扑版本可被两个 Test Job 引用，两个任务创建执行时分别固化当时 Case 内容 | API 与数据库核对 | WF-R7、WF-R12 |
| WF-S6 | 无边并行工作流在运行中心显示开始—并行—汇总—完成，真实依赖边仍可区分 | 浏览器与调度结果核对 | WF-R8 |
| WF-S7 | 编排主视口无页面级滚动，超高资产列表和属性面板独立滚动 | 双视口浏览器检查 | WF-R10 |
| WF-S8 | 无脚本、零入口或多主入口 Case 均不能保存或创建执行 | Case/API 故障用例 | WF-R13 |
