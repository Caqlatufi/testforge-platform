# TestForge AI 证据诊断需求分析

> 核心业务闭环：测试工程师从确定性失败报告发起诊断，AI 只能依据该报告提供的证据生成结构化建议和证据引用；无论 AI 成功或失败，原测试结论都保持不变。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 需要排查失败原因的测试/开发工程师，以及展示证据闭环的演示者 |
| 触发场景 | Run 已形成报告，用户希望基于现有失败断言、日志和附件摘要获得排查方向 |
| 当前问题 | 确定性报告能说明“哪里失败”，但人工串联证据耗时；不受控的模型输出又可能引用不存在的信息或冒充测试结论 |
| 期望结果 | AI 返回受 Schema 约束的分类、置信度、证据引用、建议和缺失证据，所有引用均能回到输入报告 |
| 业务价值 | 在不牺牲报告可信度的前提下降低故障定位成本，并明确展示 AI 建议与确定性事实的边界 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 测试工程师 | 在报告页查看 Provider 状态并发起诊断 | 系统按 reportId 和 requestKey 判断幂等状态 |
| 2 | AI 诊断能力 | 读取报告域提供的确定性证据 | 对证据稳定排序、裁剪并计算 evidenceHash |
| 3 | AI 诊断能力 | 查找相同证据的成功结果 | 非强制刷新时可复用结果，并记录本次 requestKey |
| 4 | Provider | 在隔离临时目录中接收受控 Prompt 并生成结构化输出 | 输出受 JSON Schema 约束 |
| 5 | AI 诊断能力 | 校验分类、置信度和每个 evidenceId | 合法结果保存为 SUCCEEDED；非法或调用失败保存为 FAILED |
| 6 | 测试工程师 | 查看 AI 辅助建议 | 页面同时保留原报告，并显示 Provider、模型、证据和复用状态 |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响的流程步骤 |
| --- | --- | --- | --- |
| AI-R1 | 诊断只读取 ReportEvidence，不直接读取报告表或修改报告数据 | 获取证据 | 2 |
| AI-R2 | reportId+requestKey 唯一；成功请求可重放，运行中或已失败的旧 key 不重复执行 | 发起诊断 | 1 |
| AI-R3 | 未强制刷新时，相同 reportId 和 evidenceHash 的成功结果可以复用 | 缓存判断 | 3 |
| AI-R4 | Provider 输出必须通过 JSON Schema，并由业务层再次校验分类和 0～1 置信度 | 输出处理 | 4、5 |
| AI-R5 | 输出的每个 evidenceId 必须属于本次输入证据集，否则整次诊断失败 | 证据校验 | 5 |
| AI-R6 | Provider 在临时目录、临时会话和只读 sandbox 中运行，完成后清理临时文件 | 模型调用 | 4 |
| AI-R7 | Provider 并发受限；未启用、未登录、繁忙、超时和非法输出必须可区分 | readiness 和调用 | 1、4、5 |
| AI-R8 | AI 诊断不得修改 Run、Task、Attempt、TestResult、失败分类或通过率 | 全流程 | 1～6 |
| AI-R9 | 报告页必须在点击前判断报告是否存在以及 Provider 是否启用/就绪；不可用时禁用按钮并显示原因，不用失败请求代替能力提示 | 报告页交互 | 1、4 |

## 4. 异常分支

| 编号 | 异常场景/触发条件 | 系统处理 | 用户或调用方可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| AI-E1 | reportId 不存在或尚无结果 | 不启动 Provider | 返回报告不可诊断原因 | 不创建成功诊断 |
| AI-E2 | 同一 requestKey 正在执行或此前失败 | 拒绝重复调用，要求等待或使用新 key | 返回进行中/旧请求失败 | 原诊断记录不变 |
| AI-E3 | Provider 未启用、未登录或并发已满 | 不影响报告，返回对应降级状态 | 报告可见，生成按钮禁用或提示稍后重试 | 诊断不成功 |
| AI-E4 | Provider 超时、退出异常或未输出结构化结果 | 终止进程并记录 FAILED | 用户看到稳定错误原因 | 原报告保持不变 |
| AI-E5 | 输出分类、置信度或 evidenceId 非法 | 拒绝整个输出并记录 FAILED | 不展示未经验证的建议 | 原报告保持不变 |
| AI-E6 | 报告没有可引用证据 | 返回 UNKNOWN、缺失证据和补充建议，不虚构引用 | 用户看到证据不足 | 可形成受限成功结果 |

## 5. 本期包含

> 本期只实现下表明确列出的内容；未列出的能力一律不属于本期，不顺带扩展。

| 编号 | 能力或场景 | 完成边界 |
| --- | --- | --- |
| AI-IN1 | Provider 状态 | Codex CLI 启用状态、登录 readiness、模型和 reasoning effort 展示 |
| AI-IN2 | 同步诊断 | requestKey 幂等、evidenceHash 复用和 forceRefresh |
| AI-IN3 | 输出控制 | JSON Schema、业务枚举、置信度和 evidenceId 双重校验 |
| AI-IN4 | 结果记录 | SUCCEEDED/FAILED、Provider 元数据、耗时、错误和最新成功结果 |
| AI-IN5 | 报告页交互 | 辅助建议标识、证据引用、缺失证据和不可用降级 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 | 对应流程/规则 |
| --- | --- | --- | --- |
| AI-S1 | 真实已登录 Provider 能对失败报告生成结构化诊断，全部 evidenceId 可回溯到输入证据 | 执行真实 Provider smoke 并逐项比对证据 | 流程 1–6，AI-R4、R5 |
| AI-S2 | 相同 requestKey 不重复调用 Provider，相同证据可复用，forceRefresh 使用新 key 生成新记录 | 组合执行幂等、复用和强刷场景 | AI-R2、R3 |
| AI-S3 | 未登录、繁忙、超时、进程失败和非法输出均形成可区分结果 | 分别注入 Provider 故障 | AI-R7、AI-E3～E5 |
| AI-S4 | 任意诊断失败后，原报告、通过率和失败分类完全不变 | 诊断前后比较权威报告 | AI-R8 |
| AI-S5 | Provider 不可用时报告页仍可查看报告和历史成功诊断 | 关闭 Provider 后打开报告页 | AI-E3 |
| AI-S6 | 无报告、Provider 未启用或未就绪时诊断按钮不可点击且原因可见；就绪后自动恢复 | 页面状态组合测试 | AI-R9 |
