# TestForge YAML Case 与托管测试资源需求分析

> 核心业务闭环：测试工程师或 AI 在 TestForge 内编写完整 Case YAML，上传或内联真正可执行的脚本资源，校验后保存；引用该 Case 的 Workflow 后续执行自动使用当前定义，而每个 Run 在创建时固化独立执行快照。

## 1. 目标

| 项 | 内容 |
| --- | --- |
| 目标用户/系统 | 测试工程师、AI Agent、Workflow 编排器、跨平台 Worker |
| 触发场景 | 新建或修改接口脚本、Python/pytest 脚本、Airtest `.air` 包及其执行资源 |
| 当前问题 | Case 页面只维护元数据；脚本通过 `sourceRef` 指向开发机绝对路径并要求用户手工维护 ScriptVersion/checksum，其他 Worker 无法取得真正测试内容 |
| 期望结果 | Case YAML 同时表达测试意图、执行需求、参数和脚本引用；脚本内容由 TestForge 上传保存；用户不再管理脚本版本 |
| 业务价值 | 测试资产不依赖某台电脑，可被人和 AI 统一编辑、校验、编排、固化和跨机器执行 |

## 2. 核心业务流程

| 步骤 | 执行者 | 动作 | 系统响应或状态变化 |
| --- | --- | --- | --- |
| 1 | 测试工程师/AI | 选择项目并新建 Case | 返回带默认结构的 YAML 草稿 |
| 2 | 测试工程师/AI | 直接编写 YAML；短 Python 可内联，Airtest 或多文件脚本上传为资源包 | 上传资源由 TestForge 保存并返回 `testforge://assets/{id}` 引用 |
| 3 | 编辑器/CLI | 将上传结果插入 YAML 并执行校验 | 校验语法、Schema、执行器组合、资源归属、入口文件和参数定义 |
| 4 | 测试工程师/AI | 保存 YAML Case | 保存原文、摘要和查询投影，不生成 ScriptVersion |
| 5 | Workflow 编排器 | 引用 Case 并发布 Workflow | 保存 DAG 拓扑与 `caseId` 引用，不复制可变 Case 内容 |
| 6 | 运行编排器/Worker | 创建并执行 Run | 创建时解析当前 Case，固化资源 URI、入口、摘要和执行需求；Worker 只读取 Run 快照 |

## 3. 关键规则

| 编号 | 规则 | 生效条件 | 影响步骤 |
| --- | --- | --- | --- |
| TA-R1 | YAML 是 Case 的唯一可编辑真相源；列表字段、执行需求和参数均由 YAML 解析投影 | 校验、保存 | 1～4 |
| TA-R2 | PROJECT Case 与 Asset 只能被所属 Project 使用；SHARED Case 可跨项目编排，但它引用的资源必须属于平台共享域 | 上传、保存、发布 | 2～5 |
| TA-R3 | 用户不创建或选择 ScriptVersion；资源只以 UUID 与 SHA-256 标识内容，历史可复现性由 Run execution snapshot 保证 | 保存、执行 | 4～6 |
| TA-R4 | `inline` 适合单文件 Python/pytest；`asset` 支持 `.py`、`.zip` 和 `.air.zip`；Airtest 必须提供可验证入口文件 | 校验 | 2、3 |
| TA-R5 | TestForge 不接受 `C:\...`、`E:\...`、`/home/...` 等本机脚本路径作为新 Case 的执行资源 | 保存、发布 | 3～5 |
| TA-R6 | Workflow 草稿和发布拓扑只引用 `caseId`；创建 Run 时读取 Case 当前定义并固化，Run 创建后不再回读最新 Case | 编排、执行 | 5、6 |
| TA-R7 | Asset 内容不可原地修改；替换脚本就是上传新 Asset 并修改 Case YAML，但不向用户暴露版本列表 | 上传、编辑 | 2～4 |
| TA-R8 | 旧 ScriptVersion、Suite 和已发布快照保持只读/执行兼容；新页面、CLI 和新建流程不再写入它们 | 兼容读取 | 4～6 |
| TA-R9 | 一个可执行 Case 必须声明且只声明一个主 Asset/内联脚本和一个执行入口；主包可含辅助文件，但零入口或多主入口均拒绝 | 编辑、保存、执行 | 2～6 |
| TA-R10 | ZIP 文件名不是执行入口；平台只接受恰好一个包内 `.air` 根或顶层 `.py` 主入口，不提供多入口选择 | 上传、编辑、校验 | 2～4 |
| TA-R11 | Case 编辑器右侧只展示当前 Case 已绑定或待保存的主脚本；上传表示替换当前 Case 的绑定，不把项目历史 Asset 暴露成可随意共享的脚本列表 | 编辑、保存 | 2～4 |

## 4. 异常分支

| 编号 | 异常场景/触发条件 | 系统处理 | 用户或调用方可见结果 | 最终状态 |
| --- | --- | --- | --- | --- |
| TA-E1 | YAML 语法错误、未知字段或必填字段缺失 | 拒绝校验/保存并返回行列或字段路径 | 编辑器定位错误 | 原 Case 不变 |
| TA-E2 | Asset 不存在、跨项目、摘要不符或入口文件非法 | 拒绝保存/发布 | 返回稳定资源错误 | 不产生无效引用 |
| TA-E3 | 上传文件为空、超限或 ZIP 含绝对路径/`..` 穿越 | 拒绝上传 | 显示具体原因 | 不保存 Asset |
| TA-E4 | Worker 下载失败或摘要不一致 | Attempt 以资源基础设施错误结束，可按策略重试 | 运行中心显示下载/校验失败 | Run 快照不变 |
| TA-E5 | 旧 Case 尚未迁移为 YAML | 通过 legacy reader 继续解析最后一个 ScriptVersion | 页面提示只读兼容，可转换为 YAML | 历史执行继续可用 |

## 5. 本期包含

| 编号 | 能力或场景 | 完成边界 |
| --- | --- | --- |
| TA-IN1 | YAML-first Case | 默认模板、读取、校验、创建、更新和摘要投影 |
| TA-IN2 | 平台托管 Asset | 项目内上传、列表、元数据、内容下载、SHA-256 与大小限制 |
| TA-IN3 | YAML 编辑工作台 | 左侧 Case、中央全高 YAML 编辑器、右侧资源库；上传后自动插入引用 |
| TA-IN4 | Run 执行快照 | Workflow 拓扑引用 Case；Run 创建时固化定义、资源 URI、摘要与执行需求 |
| TA-IN5 | Worker 资源解析 | 下载 `testforge://assets/{id}`，安全解包、摘要校验并执行 pytest/Airtest |
| TA-IN6 | AI/CLI 接入 | Case validate/create/apply/export 与 Asset upload/list/get 命令 |
| TA-IN7 | 旧模型兼容 | ScriptVersion 只读执行兼容，新写入口退出主流程 |
| TA-IN8 | Playwright UI Case | YAML 声明 `playwright-web` 与 Python 主脚本；每个 Case 绑定自己的脚本资源并由运行快照固化 |

## 6. 成功标准

| 编号 | 可验证结果 | 验证方式 | 对应流程/规则 |
| --- | --- | --- | --- |
| TA-S1 | 用户只编辑一份 YAML 即可创建可编排 Case，列表名称和执行摘要来自 YAML | API 与浏览器验收 | TA-R1 |
| TA-S2 | 上传 Python/Airtest 资源后页面返回 URI 并插入 YAML，不再填写本机路径和 checksum | 上传与页面验收 | TA-R3、TA-R5、TA-R7 |
| TA-S3 | Case 修改后无需重发 Workflow；旧 Run 保留旧资源摘要，新 Run 使用新内容 | 同一 WorkflowVersion 的两次 Run 快照对比 | TA-R3、TA-R6 |
| TA-S4 | Worker 在不同目录/机器上能下载托管资源、校验摘要并执行，不依赖控制面文件系统 | Worker 集成测试 | TA-R4、TA-R5 |
| TA-S5 | 页面和 CLI 不再出现 scripts list/create、ScriptVersion vN 或 sourceRef/checksum 手填流程 | UI、CLI 能力发现 | TA-R3、TA-R8 |
| TA-S6 | 非法 YAML、跨项目 Asset 和危险 ZIP 均被稳定拒绝且不污染数据 | API 负向验收 | TA-E1～TA-E3 |
