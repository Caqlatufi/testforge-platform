# 配置与凭据

本页供使用者在自己的电脑上启动 TestForge。复制根目录 `.env.example` 为未跟踪的 `.env.local`，填写自己的配置。`scripts/start.ps1` 和 `scripts/dev.ps1 -Component Backend` 会读取该文件；单独运行 Worker、MCP 或 Docker Compose 时，应将对应变量注入其进程环境，不能假定它们自动读取 `.env.local`。

## 1. 最小本地配置

| 类别 | 变量 | 默认/要求 | 说明 |
| --- | --- | --- | --- |
| API | `TESTFORGE_SERVER_ADDRESS` | `127.0.0.1` | 默认仅本机；可信网络跨主机访问时才显式改为监听地址 |
| API | `TESTFORGE_SERVER_PORT` | `8081` | 控制面端口；开发前端代理随该变量更新 |
| Web | `TESTFORGE_CLIENT_PORT` | `5174` | start.ps1 启动的前端端口 |
| MySQL | `TESTFORGE_DB_URL`、`MYSQL_USER`、`MYSQL_PASSWORD` | 本地默认 | 状态真相源；默认值对应本地 Compose，连接已有数据库时填写自己的账号 |
| Redis | `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD` | 本地默认 | 派发和短期协调；不能作为唯一状态源 |
| Jenkins | `TESTFORGE_JENKINS_URL`、`TESTFORGE_JENKINS_FOLDER`、`TESTFORGE_JENKINS_CREDENTIAL_REF` | URL 默认本机 | 平台级连接；项目只保存 Pipeline 标识 |
| 回调 | `TESTFORGE_CICD_CALLBACK_BASE_URL` | `http://127.0.0.1:8081` | 必须能被 Jenkins Agent 访问 |

## 2. Codex AI 诊断

AI 默认关闭。启用前在运行 TestForge 的专用 OS 账号下建立独立 Codex Home：

```powershell
$env:CODEX_HOME = 'C:\TestForge\codex-home'
codex login
$env:TESTFORGE_AI_CODEX_HOME = $env:CODEX_HOME
$env:TESTFORGE_AI_ENABLED = 'true'
```

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `TESTFORGE_AI_ENABLED` | 是 | 显式设为 `true` 才启用 |
| `TESTFORGE_AI_CODEX_HOME` | 启用时必填 | TestForge 专用 Codex Home；禁止使用或复制开发者个人 Codex Home |
| `TESTFORGE_CODEX_COMMAND` | 否 | Codex CLI 路径，默认 `codex` |
| `TESTFORGE_AI_MODEL` | 否 | 诊断模型 |
| `TESTFORGE_AI_REASONING_EFFORT` | 否 | 推理强度 |
| `TESTFORGE_AI_TIMEOUT` | 否 | 单次诊断超时，默认 `90s` |
| `TESTFORGE_AI_MAX_CONCURRENCY` | 否 | 同时诊断数，默认 `1` |
| `TESTFORGE_AI_MAX_EVIDENCE`、`TESTFORGE_AI_MAX_EVIDENCE_CHARS`、`TESTFORGE_AI_MAX_PROMPT_CHARS` | 否 | 证据和 Prompt 上限 |

TestForge 启动 Codex 时会清空继承环境，仅保留操作系统、临时目录、证书和代理等运行所需变量，再注入专用 `CODEX_HOME`。数据库、Redis、OSS、Jenkins 密钥不会传给 Codex 子进程。日志证据仍会经过敏感字段、Bearer/JWT、常见 Token 和带密码 URL 的脱敏；这不是数据分类替代品，敏感业务 Evidence 不应送入外部模型。

独立 `CODEX_HOME` 只分离 CLI 配置和登录缓存，环境变量白名单只限制变量继承；它们不构成文件系统隔离。同一 OS 用户仍可能读取其有权限访问的本机文件，专用目录也由使用者自行配置，代码不会验证它是否与个人目录相同。

Codex CLI 登录信息可能保存在 OS 凭据存储或 `CODEX_HOME/auth.json`，后者含访问令牌，绝不能提交或共享。官方说明见 [Codex authentication](https://developers.openai.com/codex/auth) 和 [Sandbox security](https://developers.openai.com/api/docs/guides/agents-api/environments/security)。自动化环境优先使用专用主体和短期凭据；支持时采用 [Workload identity federation](https://developers.openai.com/api/docs/guides/workload-identity-federation)。

## 3. 对象存储

`TESTFORGE_OSS_ENABLED` 默认为 `false`。启用时由服务运行环境提供 `TESTFORGE_OSS_ENDPOINT`、`TESTFORGE_OSS_BUCKET`、`TESTFORGE_OSS_PREFIX`、`TESTFORGE_OSS_ACCESS_KEY_ID` 和 `TESTFORGE_OSS_ACCESS_KEY_SECRET`。不要把永久密钥放入 Case YAML、Workflow、数据库业务字段、前端配置或 Worker。

## 4. Worker 与 Evidence

Worker 的核心变量为 `TESTFORGE_GATEWAY_URL`、`TESTFORGE_REDIS_URL`、`TESTFORGE_RUNNER`、`TESTFORGE_STREAM`、`TESTFORGE_WORKER_ID`、`TESTFORGE_WORKER_CAPABILITIES` 和 `TESTFORGE_WORKER_CONCURRENCY`。UI 环境再配置 `TESTFORGE_ENVIRONMENT_ID`、`TESTFORGE_DEVICE_ID`、`TESTFORGE_DEVICE_URI` 与受控的 `TESTFORGE_SANDBOX_COMMAND_JSON`。完整含义见 [Worker 配置](../../testforge-worker/README.md)。

Evidence 后端由 `TESTFORGE_ARTIFACT_BACKEND` 选择。MinIO 兼容模式使用 `TESTFORGE_MINIO_ENDPOINT`、`TESTFORGE_MINIO_ACCESS_KEY`、`TESTFORGE_MINIO_SECRET_KEY` 和 `TESTFORGE_MINIO_BUCKET`；填写自己本机 MinIO 的连接信息。

## 5. MCP

MCP 用户自行配置 `TESTFORGE_URL`、`TESTFORGE_WORKSPACE`、可选 `TESTFORGE_BINDINGS`、`TESTFORGE_TIMEOUT` 和 `TESTFORGE_TOKEN`。当前平台没有内建 Bearer Token 校验，本机默认留空 `TESTFORGE_TOKEN`。详见 [MCP 配置](../../testforge-mcp/README.md)。

## 6. Jenkins 本地示例

`infra/compose.jenkins.yaml` 默认只映射 `127.0.0.1:8082`，并保留 CSRF 防护。可配置 `TESTFORGE_JENKINS_BIND_ADDRESS`、`TESTFORGE_JENKINS_PUBLIC_URL`、`TESTFORGE_GATEWAY_URL`、`TESTFORGE_SCM_MIRROR_URL` 和三个 Agent Remote FS 变量。该 Compose 仍是无完整认证治理的本地开发环境，不是生产模板。
