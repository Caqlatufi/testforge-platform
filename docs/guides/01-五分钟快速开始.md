# 五分钟快速开始

本指南启动 TestForge 的本地控制面：MySQL、Redis、MinIO、Spring Boot API 和 Vue Web Console。完成后可以浏览页面并管理 Project、Case、Workflow 和 Test Job。

完整测试执行还需要 Jenkins 与 Worker，请在完成本指南后继续阅读[端到端演示](03-端到端演示.md)。

## 1. 环境要求

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Windows | 10/11 | 当前一键启动脚本的运行环境 |
| PowerShell | 5.1+ | 执行平台脚本 |
| Java | 21 | Spring Boot 控制面 |
| Node.js | 22.12+ | Web Console |
| Python | 3.10+ | 完整 E2E、Worker 与验收需要；本页控制面启动不需要 |
| Go | 1.25+ | 构建 TestForge MCP 需要；本页控制面启动不需要 |
| Docker | Compose v2 | MySQL、Redis 与 MinIO |

检查关键工具：

```powershell
java -version
node --version
python --version
go version
docker version
docker compose version
```

## 2. 启动

在克隆得到的 `testforge-platform` 仓库根目录执行：

```powershell
# 已位于包含 scripts/ 的仓库根目录
# 如需自定义配置，复制 .env.example 为 .env.local 后填写
.\scripts\start.ps1
```

脚本依次完成：

1. 读取未纳入 Git 的 `.env.local`（存在时）；
2. 启动 MySQL、Redis、MinIO 和初始化任务；
3. 安装 Web Console 依赖；
4. 启动 Spring Boot API；
5. 启动 Vite Web Console；
6. 等待 API Health 变为 `UP`。

已有前端依赖时可以跳过安装：

```powershell
.\scripts\start.ps1 -SkipInstall
```

## 3. 验证

| 检查项 | 地址或操作 | 预期结果 |
| --- | --- | --- |
| API 健康 | <http://127.0.0.1:8081/actuator/health> | `status` 为 `UP` |
| Web Console | <http://127.0.0.1:5174> | 显示测试任务主页 |
| 项目页 | 点击“被测项目” | 可以查看或创建 Project |
| 环境页 | 点击“环境资源” | 可以查看环境实例状态 |

运行日志位于仓库内 `build/local-runtime`：

```text
backend.out.log
backend.err.log
client.out.log
client.err.log
```

## 4. 停止

```powershell
.\scripts\stop.ps1
```

该命令停止 Java、Vue、MySQL、Redis 和 MinIO 进程，但保留 Docker 命名卷。它不会清空 Project、Case 或任务数据。

## 5. 常见问题

### API 一直未就绪

检查 `build/local-runtime/backend.err.log`，并确认 3306、6379、9000、8081 没有被其他服务占用。

### 页面能打开但任务一直等待

控制面启动不等于执行资源已启动。运行页应分别显示脚本执行槽、UI 测试机和在线 Agent 容量；对应能力为零时，Case 会等待兼容 Worker，而不会随机分配到错误执行器。

### 为什么没有自动启动 Jenkins 和虚拟机

Jenkins、Windows VM 和 UI Agent 属于真实交付与执行环境，生命周期和凭据不应被基础启动脚本隐式控制。完整配置见[端到端演示](03-端到端演示.md)。

### 如何清空本地数据

停止脚本默认保留数据。清理命名卷属于破坏性操作，应先确认 Compose 项目名和目标环境，再按[基础设施说明](../../infra/README.md)手工执行。

端口冲突时可在 `.env.local` 设置 `MYSQL_PORT`、`REDIS_PORT`、`MINIO_API_PORT`、`MINIO_CONSOLE_PORT`、`TESTFORGE_SERVER_PORT` 和 `TESTFORGE_CLIENT_PORT`。多个实例应设置不同的 `COMPOSE_PROJECT_NAME`；如显式配置 `TESTFORGE_DB_URL`，其端口和库名也须对应调整。
