# TestForge 开源文档体系

## 1. 文档目标

开源文档围绕一个读者闭环组织：访问仓库后能在两分钟内判断项目用途，在五分钟内启动控制面，在一条完整指南中跑通测试链路，并能明确知道如何贡献、报告安全问题和核对项目成熟度。

## 2. 信息架构

```text
仓库根 README
├─ 项目价值、能力边界、架构全景
├─ 五分钟启动
└─ 按目标分流
   ├─ 试用者 -> docs/guides/01-五分钟快速开始.md
   ├─ 使用者 -> docs/guides/02-核心概念.md
   ├─ 演示者 -> docs/guides/03-端到端演示.md
   ├─ 视频作者 -> docs/guides/04-项目全流程视频脚本.md
   ├─ AI 用户 -> testforge-mcp/README.md
   ├─ 贡献者 -> CONTRIBUTING.md
   ├─ 安全研究者 -> SECURITY.md
   └─ 深度评审者 -> docs/README.md
```

## 3. 文档分层

| 层级 | 读者问题 | 权威文件 | 写作要求 |
| --- | --- | --- | --- |
| Landing | 这是什么，值不值得继续看？ | 根 `README.md` | 先价值和闭环，后技术栈；命令必须可复制 |
| Guide | 我怎样启动、理解和跑通？ | `docs/guides` | 按用户操作顺序；区分最小启动和完整环境 |
| Component | 单个组件怎样配置？ | 各模块 `README.md` | 只维护该组件安装、配置、接口和故障定位 |
| Design | 为什么这样设计？ | 十个功能域文档 | 需求、架构、开发、验收职责分离 |
| Evidence | 真的跑通过吗？ | `acceptance/evidence` | 绑定 Commit、环境、命令和原始结果 |
| Community | 怎样参与和报告问题？ | `CONTRIBUTING.md`、`SECURITY.md` | 规则清晰，不暴露私人联系方式或凭据 |
| Release | 是否可以公开发布？ | `开源发布清单.md` | 每项必须有完成状态与证据 |

## 4. 单一事实来源

| 事实 | 唯一维护位置 | 其他文档处理方式 |
| --- | --- | --- |
| 产品定位与首次入口 | 根 README | 链接，不复制长篇介绍 |
| 平台业务模型 | `docs/README.md` 与各功能域 | Guide 用用户语言摘要 |
| 启动命令 | `docs/guides/01-五分钟快速开始.md` | README 只保留最短命令 |
| 完整演示操作 | `docs/guides/03-端到端演示.md` | 视频脚本引用，不维护第二套流程 |
| MCP 配置 | `testforge-mcp/README.md` | README 和 Guide 只给入口 |
| Worker 变量 | `testforge-worker/README.md` | 端到端指南只给最小示例和链接 |
| Jenkins 连接 | `infra/README.md` | Guide 只列演示前检查 |
| 配置与凭据 | `docs/guides/05-配置与凭据.md`、`.env.example` | 模块 README 只补充组件特有变量 |
| 安全边界 | `SECURITY.md`、`docs/reference/安全设计.md` | README 只保留阻断性提示 |
| 验收状态 | 功能验收文档与 Evidence | README 不把 NOT_RUN 写成已通过 |

## 5. 公开写作规则

1. 使用 Project、Case、Workflow、Test Job、Environment、Worker、Attempt 和 Report 的当前模型，不再使用已废弃 Suite、独立 Run 主对象或 Python CLI。
2. “一键启动”必须写清实际启动了哪些进程；不能把 Jenkins、Worker、VM 或真实 E2E 隐含在内。
3. 命令优先从仓库脚本引用，端口和环境变量必须与代码一致。
4. 任何“生产级”“高可用”“完全通过”表述都必须有可公开复核证据；否则写明适用范围。
5. 截图不得包含真实 Token、私有 URL、用户目录或历史脏数据。
6. 中文为当前主文档语言；未来新增英文版时按内容等价维护，不建立内容分叉。
7. README 保持可扫读；设计争议、完整字段和验收矩阵留在功能域文档。

## 6. 维护触发器

| 变更 | 必须同步检查 |
| --- | --- |
| 启动脚本、端口或依赖版本变化 | 根 README、快速开始、贡献指南 |
| 业务对象或状态模型变化 | 核心概念、端到端演示、视频脚本 |
| 新增 Runner 或 Provider | Worker README、资源调度文档、端到端演示 |
| MCP Tool、变量或发布方式变化 | MCP README、根 README、视频脚本 |
| UI 导航或按钮名称变化 | 端到端演示、视频脚本、截图 |
| 发布新版本 | Release Notes、支持范围、证据索引、发布清单 |
